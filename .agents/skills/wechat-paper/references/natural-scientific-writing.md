# 中文科研公众号的自然写作审校

本指南是公众号导读“去 AI 味”的执行流程。文章结构与写作规则以
`wechat/STYLE.md` 为准；本文件负责逐段、逐句的审校方法和示例。

目标是**清楚、简洁、可核对**：读者读完能说出论文解决什么问题、改了哪里、证据和
边界在哪里。验收看读感和事实一致性，不看 AI 检测分数，也不看字数减少多少。

通用中文改写规则固定在 [vendor/humanizer-zh](vendor/humanizer-zh/PROVENANCE.md)
（MIT 许可，仅作本地参考，不执行外部程序、不上传稿件、不自动更新）。
与本项目科研事实边界冲突时，以本项目规则为准。

## 1 每篇执行六步

1. **事实核对单**：列出要用的结论、数字（含指标、基线、工况）、原文定位、限制与
   确定程度。原文内部矛盾照实保留。
2. **一条论证线**：用一句话写出“现有做法在 X 情况下不够 → 本文改了 Y → 用 Z 检验，
   结果是 W，适用到 V 为止”。写不出这句话，先回到论文，不要动笔润色。
3. **先改结构**：保留摘要的忠实翻译，删去导语、新增“研究问题与解决思路”、后续正文
   与结尾之间没有新信息的复述。新增栏目按 STYLE 第 6 节帮助读者把握问题主线；
   后续论证小标题改成具体句子，每节只承担一个任务（方法 / 证据 / 边界等）。
4. **再改句子**：按第 2 节的清单逐段检查。
5. **对照核对单**：数字、单位、工况、比较基线、随机实现筛选、潜在用途与已验证对象
   逐项对回。不能把“可能”改成“证明”，把局部结果写成普遍改进。
6. **通读并记录**：开头是否直接进入问题，每段是否推进理解，术语是否解释，结尾是否
   具体。改动与保留的事实记入 review（已有核验的 review 不宜改动时，另建
   `<publication_ref>.language.review.md`）。内容改动后，旧的上传与预览证据只算历史。

## 2 本项目常见的 AI 腔与改法

以下示例取自本仓库早期稿件，改写只使用原句已有的信息。

### 2.1 结构层面

| 问题 | 表现 | 改法 |
| --- | --- | --- |
| 模块重复 | 导语、摘要、新增栏目和后续正文各讲一遍同样的结论 | 保留忠实摘要；新增栏目只梳理问题与思路；后续展开机制、证据和边界，压缩重复铺垫 |
| 空壳标题 | 后续论证节沿用“研究问题”“方法贡献”“关键发现”“工程意义” | 改成具体句子，如“过渡区留多长，分块计算才可信？”；STYLE 规定的固定“研究问题与解决思路”栏目是明确例外 |
| 编号回扣 | “针对问题 1，……”“针对问题 2，……” | 删去编号，用一句承上启下的话直接进入 |
| 要点化论证 | 因果关系被拆成五条并列 bullet | 论证写成段落；列表只留给真正并列的条件 |
| 固定结尾 | 每篇都是“如果你对……感兴趣，点击阅读原文……” | 一句说明阅读原文里有什么；导流用 STYLE 的统一尾注 |
| 方向自述 | “这项工作属于 WOEAI 的……方向，也与……直接相关” | 方向放进论文信息；正文不重复 |

### 2.2 句子层面

**拔高式对比（“不只是……而是……”）**

- 改前：这篇论文的价值不只是提出一个算法，而是把城市微尺度风环境评估向“可数据库化、可平台化、可快速调用”的方向推进了一步。
- 改后：论文把城市片区的 CFD 结果预先算好并入库，后续评估改为查询，而不是每次重新建模计算。

**“我们”开头的口号句**

- 改前：我们的核心思路是建立一个**基于区块的城市微尺度风场预计算 CFD 数据库**。
- 改后：做法是把城市切成 $1\,\mathrm{km} \times 1\,\mathrm{km}$ 的区块，逐块算好 CFD，再把结果整理成数据库。

**解释公式时的空话**

- 改前：这条公式的含义很直接：我们不是只看某个风速值是否相同，而是比较……
- 改后：比较的是风速比，而不是风速本身：测点风速除以参考站风速，再看 CFD 与实测是否一致。

**图注复述论点**

- 改前（读图行）：预计算 CFD 数据库不只停留在离线计算结果中，也可以进一步进入查询、展示和工程沟通平台。
- 改后（读图行）：对照原图写明分图位置、色标或线型含义和应关注的区域，例如“左图为……，右图为……；色标表示……”。不确定的内容不写。

**套话收尾**

- 改前：所以，更准确的理解是：预计算 CFD 数据库适合承担快速筛查、方案比较和工程沟通的前置角色。
- 改后：它适合在方案阶段做快速筛查和比较；对特殊建筑形态或高风险区域，仍要做专项 CFD 复核。

### 2.3 词语提示

下面的词不是禁用词，命中时检查是否空泛、重复或比证据更强：

- 拔高：赋能、闭环、全面、颠覆、突破、首次、重大、显著（没有统计检验时）、彰显、标志着。
- 铺垫：值得注意的是、需要指出的是、众所周知、随着……的发展、在……背景下、接下来让我们看看。
- 套话：具有重要意义、提供了新思路、奠定了基础、具有广阔的应用前景、为……提供有力支撑。
- 模糊因果：使得、从而、进而（连用三个以上时检查因果是否都有证据）。
- 堆叠：“的”连用三次以上、“进行＋动词”、连续被字句、四字词排比。

### 2.4 好的写法长什么样

范文 `wechat/articles/draft-public-safe/ref-chen2024-JCP.md` 的几个特点：

- 小标题是问题句：“风速谱对了，风压为什么还可能算偏？”“相干与压力怎样检验，结果适用到哪里？”
- 数字带位置和条件：“HA2 在 $x/M=30$ 处……约 $12\%$ 动压量级；HA1 中心……约 $1.5\%$”，
  并紧跟一句“两个数对应不同位置，不能直接换算成普遍的降幅”。
- 限制写在结论旁边：“三个速度分量共用这组波数……并不意味着三个分量的任意相干函数
  都可以分别指定。”
- 用途与已验证分开：“建筑风压与城市微尺度风环境是潜在应用方向；迁移过去，还需要……”

## 3 保留，不要改掉

- 论文信息、忠实中文摘要、原图图号与两行图注、关键公式。
- 原文的限定、否定、比较对象、确定程度和归因。
- 原文内部矛盾及其说明。
- 已确认的封面文案（改动需重新确认）。

## 4 交付检查

- [ ] 能用一句话写出论证线，且正文按这条线推进。
- [ ] 首段可以单独作为微信摘要（约 60–110 字）。
- [ ] 摘要之外，没有任何一节是摘要的扩写。
- [ ] 每个数字都有指标、基线和条件；局部最好值没有写成普遍改进。
- [ ] 第 2 节的结构和句子问题已逐项检查。
- [ ] 没有新增原文不支持的事实、经历、情绪、动机或因果。
- [ ] 延伸阅读只含已发布的公众号文章，否则整节省略。
- [ ] 公式在实际微信手机的浅色、深色模式分别检查（见 `wechat/README.md`）。
